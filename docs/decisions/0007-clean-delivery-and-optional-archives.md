# 0007 — 默认纯净交付，诊断归档按需保留

状态：已实现，待真实宿主复测。依据：用户提供的 0.0.7 Claude/AGY 使用目录。

## 问题

Claude 一次成功运行留下 10 个文件；AGY 五次运行留下 37 个文件（均不含用户要求的 process.txt）。流水线每次固定保存输入、Master、Variant、HTML、PDF、QA、manifest，随后复制 HTML/PDF 到交付目录。`--summary` 只精简终端输出，没有解决实际文件数量。AGY 又为模板比较与交付复制重复构建。

## 决定

默认 `forge` 在系统私有临时目录完成相同的事实归一化、来源链、模板装配和 PDF 验收；成功仅发布当前 HTML/PDF，普通成功或失败都清理本次临时目录。默认使用简短结果和 `manifest: null`，不以另一个隐藏目录或压缩包把冗余产物换个位置永久保存。

新增 stdin 输入（`--profile-json -`），宿主可在内存准备事实，不再必须创建 profile.json。后续修改以可编辑 HTML 为当前画布，通过 `--html-input -` 提交内存中的修改，同一流水线验收并发布二者；不先覆盖当前 HTML、不从渲染结果逆向构造 Master，也不把未显示的候选人事实嵌入公开 HTML。

`--keep-workspace` 明确保留完整诊断。显式 `--workspace` 为兼容入口，仍启用完整归档；旧调用如需纯净输出，应删除该参数。Master/Variant 语义和共享验收条件保持，改变的是保留策略而非放宽验证。

选模板先用内容和元数据判断，默认只生成一个设计。只有用户要求或真实布局缺陷才做额外比较。当前成功输出已经是交付文件，不为更换交付路径而重跑同一输入；需要不同位置时在该次构建前指定。

## 边界与代价

- 默认没有持久化完整调试记录或完整事实档案；需要跨岗位事实库、完整历史时由用户明确选择保存原始资料/归档。可编辑 HTML 保留已经呈现的内容，不能代替全部原始事实。
- 不删除已有用户文件、旧归档、用户明确要求的过程记录或过去生成的草稿。纯净保证针对本次新增产物，不是清空整个目录。
- 草稿默认输出 draft.html，避免与旧正式 PDF 混成新验收版本；它是用户明确请求的额外文档。
- 普通发布失败通过锁和回滚保留旧文件；两文件发布不是断电/崩溃下的事务。强制终止可能留下系统临时目录，当前不添加后台清理服务。
- 默认失败仍有非零退出码、空交付路径和诊断；需要完整现场时显式归档重跑。不会把已删除的临时文件作为可打开产物返回。
- HTML 输入复用浏览器验证，但不声称已重新验证原始候选人事实或重新选择模板，报告为 existing-canvas。
