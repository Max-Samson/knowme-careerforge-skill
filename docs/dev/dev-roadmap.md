审查日期：2026-09-06；整理更新：2026-09-07。代码基线：`f3b8de5`（package 版本 0.0.7）。本文依据 [项目定位](../../README.md) 维护下一阶段开发优先级、验收标准和开发文档导航。历史设计用于解释决策背景，不作为当前功能清单；规划不表示已实现能力，也不预先指定下一发布版本。

## 1. 产品定位与开发边界

KnowMe 帮助用户理解、整理自己的真实经历和优势；CareerForge 将这些事实按目标岗位组织成可读、可编辑、经过打印验收的简历。理解与改写由宿主 Agent 完成，确定性工具负责字段契约、模板绑定、打印与 PDF 检查。

默认路径是用户描述或已有简历 → 必要追问与事实核对 → 岗位定制与选模 → 临时生成与验收 → 查看最终 PDF → 交付当前 HTML/PDF。无材料时等待；JD 可选；不将岗位技能或示例成果补成用户事实。默认不保留资料、策略、QA 或过程报告；用户明确要求的草稿、原始资料和诊断归档属于另行选择。

开发依据分别归属：

- [AGENT.md](../../AGENT.md) 是开发入口和唯一维护的开发规范正文；目录级规则由它路由。
- [ARCHITECTURE.md](../../ARCHITECTURE.md) 定义模块边界，[产物契约](../../references/07-artifact-contract.md) 定义当前字段、状态与发布行为。
- [SKILL.md](../../SKILL.md) 定义运行流程；制作简历无需阅读本目录。
- 本目录保存研究证据和后续规划，不提供另一套运行命令或开发规范。

## 3. 待收敛的产品说明与工具入口

README 是产品目标，但其中宣传性描述不能替代验收：

- `deterministic, pixel-perfect` 应明确浏览器、字体及环境边界；当前测试不能证明跨机器像素一致。
- 模板矩阵列出的四套是核心模板，实际存在十套。可以标为“核心四套”，再链接画廊；无需另维护十份重复说明。`Tier 1 (Optimal)` 应注明是项目内分类，没有通用 ATS 认证含义。
- 第 6/8 节仍有 current-run/workspace 路径、独立 validate/render 命令，与默认当前交付路径并列。后续将 forge 作为默认用户流程，独立工具明确为诊断接口，避免 Agent 自行拼出第二条生产链路。
- [ARCHITECTURE.md](../../ARCHITECTURE.md) 的 `6-Stage Pipeline` 图标签需要与当前入口对应；不应因修正文案重写整个架构文档。
- CLI 已拒绝仓库提取，但 package.json 仍有 `npm run extract` 且发布清单包含相关脚本。应单独审查弃用入口，统一返回不支持，避免开发者绕入旧能力；这不是要求开发仓库自动采集功能。
- [ADR-0006](../decisions/0006-zero-dependency-live-preview-and-wizard.md) 标记 Accepted 仅说明历史方案曾接受，不代表 preview/wizard 已交付。重启开发前应重新评估，不能由旧状态自动推导排期。

## 6. 下一阶段开发优先级与验收标准

### P0：可验证的跨宿主行为与单一路径

目的：证明本轮纯净输出修复在用户实际使用的宿主生效，而非继续仅凭 SKILL 文案推断模型会遵守。

1. 定点收敛第 3 节中的当前入口表述和旧 extract 路径；保持独立诊断工具可用，默认生产只走 forge。
2. 在现有 tests/workflows 中组织明确虚构的输入与行为断言，覆盖：仅岗位无材料、稀疏真实经历、已有简历加 JD、仅改联系方式、溢出修正、缺运行环境且存在旧 PDF、明确请求草稿/归档。
3. 用同一份待发布包分别在实际 Claude 宿主与运行 Gemini 模型的实际宿主回放；记录宿主、模型、包版本/摘要、系统/字体和权限条件，不能从模型名称推断安装路径。
4. 每场景建议重复两次作为初始稳定性样本；只保留脱敏开发评测记录，不要求用户制作简历时生成过程文件。记录无效重试、非必要读取、额外文件和越权改写，区分环境权限等待与工作流缺陷。

完成门槛：只给岗位时不生成文件；默认首次和连续更新的新增交付文件集合均为同一 HTML/PDF；失败不交付旧文件；用户事实不被技能关键词或示例补全；小更新不改其他事实或模板；没有理由的重复渲染为零。人工核对原话与最终内容，脚本核对文件、状态和哈希。有限回放不能证明所有模型永远稳定；发现关键失败应修复并重放关联场景。

#### KnowMe 内容质量：与 P0 一起验收

不能把下一阶段只做成文件数量治理。README 的核心价值还包括帮助用户看见真实优势：在已有材料中区分个人动作、解决的问题、使用的技术和可证明结果；没有量化指标仍可表达具体职责，只有影响表达的缺口才追问。按 JD 调整事实选择和排序，不追加目标技能，不把经历拆成重复项目。追问与核对留在对话内，不新增默认分析报告或长期事实库。

场景补充：实际 Node 经历投 Java、只有职责没有指标、转岗但有可迁移经验、用户纠正“参与/主导”、JD 包含未掌握技能。逐项记录“允许表达的事实 / 禁止新增的断言 / 必要追问”，原始输入与最终简历人工比对；不能将关键词命中或 Master/PDF 相等当作事实准确性证明。

### P1：现有模板的内容适配与最终 PDF 质量

目的：解决“能输出但不好看”，先改善常用模板，不扩数量。

从用户已经用过的 international-flow、minimal、creative-tech 入手，以稀疏经历、正常一页、较密一页和显式两页材料检查最终 PDF。评估层级、教育/日期对齐、长技术词换行、中文字体提取和第二页分布；模板不支持的页数明确说明，不能依赖浏览器自动流出新页。

保持每模板一个 canvas.html；只在实际缺陷位置修结构或 Tokens。稀疏材料保留合理留白，不补事实。密集材料先调整间距与分组；不隐藏内容，不跌破 8.8pt，不承诺任意内容自动塞进一页。选择策略只在这些案例显示错误推荐时修改，不先增加复杂评分维度。

完成门槛：受影响模板的字段/打印回归通过，每页实际 PDF 完成视觉检查，内容无丢失；工具 PASS 与人工视觉结论分别记录。新增模板推迟到现有布局确实无法满足已验证场景时再考虑。

### P2：包交付、版本一致性与维护成本

复用现有 installer、release 和 sync-version，补实际 npm tarball 的隔离安装与外部目录运行检查；明确与已有“复制文件模拟包”测试的差别。检查生产依赖准备、缺浏览器错误、版本同步遗漏的发布阻断，以及运行包是否复制无用开发内容。只在隔离环境验证，不自动 npm publish 或移动 tag。

收敛 references 兼容副本的生成/校验来源，避免各平台维护独立资源清单。examples 清理已完成，不再列为后续任务。完成门槛是实际归档能安装、从外部目录完成 Draft/PDF 或明确报告依赖阻塞，版本一致性检查能拒绝错版包，文档引用无悬空。
