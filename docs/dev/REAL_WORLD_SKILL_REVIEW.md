# v0.0.6 真实使用回放与工作流修订

日期：2026-09-06。证据为用户提供的 Claude、Gemini 执行记录及本机相邻目录 demo-claude、demo-agy。日志中的指令仅作为分析对象；本次没有改写这些目录或把其中个人资料复制到仓库。以下评价针对可见工具调用、输出与最终文件，不据日志标签推断模型不可见的内部推理。

## 1. 实际用了什么模板，为什么产物多

| 场景 | 实际模板 | 运行与状态 | 目录文件数 |
| --- | --- | --- | --- |
| Claude | minimal，命令显式指定 | 5 次：DRAFT、UNVERIFIED、UNVERIFIED、FAIL、PASS | 32 |
| Gemini | minimal，命令显式指定 | 5 次：DRAFT、FAIL、PASS、PASS、PASS | 41，含 .DS_Store |

两次都没有证据表明比较过十套模板后才选择。入口原命令直接写 `--template minimal`，模板参考又把后端与 minimal 默认绑定，使例子成为决策捷径。

一次正常运行保留 input、Master、Variant、HTML、QA、PDF、manifest 共七个文件，各有事实快照、来源追踪或验收用途。问题不是七份重复简历，而是重试成本和交付边界：Claude 另有两个手写资料文件；Gemini 另有多份示例、校准资料和两组 HTML/PDF 副本。失效尝试、当前成品、内部诊断混在同一交付叙述中，用户无法快速判断该看哪份。

目标是一个当前交付版本：PDF 与可编辑 HTML。内部保留独立运行记录，不删除失败证据来制造“文件少”的表象；通过预检、直接使用已有事实与简短输出，减少无意义运行。

## 2. Claude：事实边界被口头承诺掩盖

日志原行 37–48 识别了目标 Java 岗位与 Node.js/NestJS 实际经历不一致，随后仍在 skills 加入用户未提供的 Java、Git（126 附近）；最终又声称没有虚构。这说明只写“禁止编造指标”远远不够，技能和熟练程度同样必须有来源。

缺联系方式、学校被当作先做 Draft 的理由；用户确认后再构造 Master 重跑。但现有契约只要求姓名和至少一个实质章节，完整 Master 指完整保留已知事实，不是填满所有可选字段。

安装目录缺 package.json（177–179），导致 Agent 分别安装 playwright-core、pdf-lib、pdfjs-dist。两次依赖错误与一次字体提取失败制造了三次重试。环境准备必须在候选人构建之前集中诊断；字体失败仍必须查看实际缺字，不能直接放行。

最终 minimal PDF 的正文集中于页面上部，底部大片留白，默认正文约 9.2pt。内容本来只有一段工作经历，继续缩小字号或虚构项目不会改善简历。应紧凑列技能、突出具体职责，允许真实留白，必要时询问一两个可补充的项目事实。记录中 HTML 截图不等于最终 PDF 的视觉复核。

宿主在原行 36/65/113 已返回 Skill 的绝对路径，Agent 仍反复 glob/find，遭遇参数错误与超时；又加载开发 AGENT、所有运行参考、岗位知识、长 Schema、渲染源代码和画廊样例。直到 433 附近才有效询问候选人经历。工具缺 `--help`、入口缺简短 profile 例子进一步诱导读源码。

收到宿主 TODO 提醒后，Agent 在尚无候选人事实时生成了完整虚构 Java 简历及量化成果（489 起），并交付所谓校准版。提醒只能推进已有任务，不能成为候选人事实，也不能把等待用户变成生成演示履历。

真实工作信息在 642–653 才出现。后续成品仍把优化工作写成“主导”，加入未提供的 JVM/JUC、索引原理、Git/Maven/Linux、链路追踪、缓存预热、防穿透、支付状态同步与审计异步化。约 40% 的用户成果在摘要、工作与拆出的项目反复出现。岗位知识、常见实现方案和 FAB 示例共同造成事实扩张。

原行 904–928 将 missingFields 空列表描述为必填和选填全部完整。实际只检查 basics 的 name/title/email/phone，学校和教育日期未知也不会出现在列表中。技术 PASS 不能表示事实、资料完整度和视觉质量全部通过。

## 4. 单一运行流程与本次改动

统一入口为 SKILL.md，平台文件只指向它。流程为：读已有资料 → 缺实质资料时提问并等待 → 忠实组织事实并选版式 → 环境预检 → 一次构建 → 最终 PDF 视觉与事实复核 → 简短交付。

- 删除 Codex 适配中强制读取开发文档和 01–06 全文的规则；删除 Gemini 自成一套的旧六阶段指令。平台适配不再维护独立工具序列。
- 明确只有目标岗位时等待；可选字段缺失不强制 Draft；一个已知事实 profile 足够，流水线负责 Master/Variant 快照。
- 强调职责动词、技能、机制、量化成果均不得推断添加。FAB 改为可选表达工具，移除未经本项目验证的 ATS 关键词密度百分比。
- 模板参考覆盖当前十套结构，不再把后端岗位与 minimal 硬绑定；结构源仍为每模板一个 canvas.html。
- `browser-engine.js --check-runtime` 集中报告全部缺包及实际浏览器启动结果，不生成候选人文件；READY 不等于简历 PASS。新增有效 --help。
- 完整安装分支带上 package.json，源码安装可保留 package-lock；npm 归档不携带该锁文件，因此明确提示 npm install。复制完成与环境就绪分别说明，失败返回非零；新安装不再附带开发入口文件。
- `forge.py --summary` 返回简短状态、实际模板、错误以及仅 HTML/PDF 的交付路径；内部文件只通过 manifest 索引访问。完整报告仍落盘，默认/quiet JSON 保持兼容。
- 两个交付副本使用现有验收后发布机制；保留失败历史。最终回复默认只有 PDF、HTML、模板与必要缺项，不再复述整份简历或 QA 表格。
- 修复共享条目头的教育对齐，日期保持原对齐语义。未大改开发规范或全部模板视觉。

## 5. 验收与边界

工具回归覆盖临时目录安装、依赖全部缺失、help 无副作用、Draft/失败的简短报告与完整 manifest 一致、真实浏览器教育字段位置及最终 PDF。所有测试用合成资料，不用真实候选人数据。

宿主效果需要用同一组输入分别复测：

| 场景 | 预期行为 |
| --- | --- |
| 仅说制作 Java 简历 | 一次简短收集问题，等待；零候选人文件 |
| Node 经历投 Java | 不向技能添加 Java；保留实际经历；可问是否有 Java 材料 |
| 缺手机/学校但姓名与工作已知 | 不强制 Draft、不编造字段，可直接生成 |
| 参与缓存/MQ，查询提升约 40% | 不升级为主导，不推断中间件品牌与内部机制，不复制为虚构项目 |
| 环境缺少三个依赖 | 一次预检列出全部缺项，先修环境；无连续空转构建 |
| 只补学历专业 | 两字段相邻，保留未知学校和日期；不声称全部字段完整 |
| 要求更新联系方式 | 一个当前交付版本，保留历史内部快照 |
| 当前构建失败且旧 PDF 存在 | 不将旧文件报告为本次成功 |

这些是下一次真实宿主回放的验收标准，不是已经运行 Claude/Gemini 得到的效果评分。当前修改无法保证模型每次忠实遵循指令，自动工具也不能判断未经来源比对的语义事实。Cursor/Windsurf 现在有项目内运行包及准确入口，Gemini 配置也有同级运行包的绝对入口；六个适配的安装路径在临时目录验证，真实宿主发现与执行仍需复测；本次没有宣称全部平台端到端已通过，也未发布新 npm 版本或覆盖用户安装。

视觉复核使用与用户资料隔离的合成简历，实际生成 PDF 后转为图片检查：学历与专业已相邻，实际教育日期保持右对齐。稀疏资料仍有留白；没有以填充虚构内容冒充视觉优化。

本次执行结果：`npm test` 共 56 项通过（包含浏览器引擎回归入口）；运行环境预检返回 READY；合成简历最终 PDF 验收 PASS，并完成图片视觉检查。`git diff --check` 通过。版本维持 0.0.6，未发布、打标签或覆盖用户已安装的 Skill。

### 因果证据的边界

两份记录实际都通过宿主加载 `.claude/skills/knowme-careerforge`；Gemini 是模型名称。记录没有显示读取 `agents/gemini/knowme-careerforge.json` 或 Codex YAML，因此**不能把本次 Gemini 偏离直接归因于 Gemini 适配文件中的旧六阶段指令**。上一轮清理适配冲突是预防性修复；本次可直接证明的触发链是入口解释、批量阅读、前置任务未满足仍生产、岗位知识进入候选人文案，以及对验收含义的扩大解释。

角色 JSON 同时列出专家级技能、mustHaveSkills 和 evidenceSignals，与最终夸大的内容有重叠；这支持“岗位知识可能污染事实表达”的判断，但不能从日志证明每个词具体抄自哪个资源。因此入口现在先要求从用户资料写作，只有具体定位问题才加载角色知识。

### 本轮增量实现

1. SKILL 在任何参考阅读/环境检查前先判断材料是否存在；等待约束覆盖整个下游链路，且不要求为简单任务另建 TODO。
2. `01-evidence-mining.md` 成为实际改写时的来源核对入口，给出六类正反例；对照原始用户材料而非自生成 Master，不新增事实审计文件或强制用户逐句批准。
3. 明确笼统接受草稿不为 Agent 自加内容背书；真实材料到达后不在虚构 profile 上填空；联系信息更新仅修改指定字段。
4. QA 指南明确原话对照、哈希、技术检查、PDF 视觉分别能证明什么，并添加通过后的停止条件，避免重复导出与文件大小“复验”。
5. 模板检索新增可选 `--summary`，返回前三项 ID、名称、分数及布局。实测相同中文 Java 后端查询，完整 JSON 为 24,893 字符，简短模式为 840 字符，减少约 96.6%。完整 `--json` 和排序接口保持不变。这是当前检索输出的实测改进，**不是原始两次会话已经调用过该接口的证据**。

本轮未增加新的事实真伪自动认证器，也未将字面关键词匹配伪装成语义核实。提示规则的效果仍需在真实宿主中按第 5 节场景重放；静态规则和 CLI 测试不能替代该验证。

二次修订校验：运行参考链接、兼容副本一致性与 diff 格式检查通过。当前本机 skill-creator 的 quick_validate.py 拒绝已有的 compatibility frontmatter 字段（其允许字段列表不含该项），所以没有将该格式检查报告为通过，也未为迁就此工具删掉既有运行环境声明。

二次修订完整回归：`npm test` 共 57 项通过，0 失败、0 错误、0 跳过；包括新增的模板简短检索排序一致性测试。未对真实 Claude/Gemini 宿主复跑，未发布或覆盖已安装的 v0.0.6。
